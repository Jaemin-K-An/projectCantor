# V1 ERRATA

V1의 결과 파일·그림·문서는 **수정하지 않는다.** 발견된 문제는 여기에 기록하고,
필요한 재실험은 `results/v2/` namespace에서 수행한다.

## A. `scripts/run_neural_ode.jl`에 벤치마크 코드가 중복되어 있었다

**문제.** V1의 `run_neural_ode.jl`은 학습 뒤에 ID/OOD 벤치마크를 이어서 실행했다.
그 코드는 이후 `scripts/run_neural_benchmark.jl`로 분리되었으나 원본에 남아
있었고, 남아 있던 쪽은 **적응형 솔버가 `maxiters = 10⁸`으로 슬라이딩 모드에서
90분 이상 정지한 바로 그 버전**이었다. 두 진입점이 서로 다른 적분기로 같은 결과
파일 이름(`neural_benchmark.csv`)을 쓸 수 있는 상태였다.

**조치 (V2 hygiene commit).** `run_neural_ode.jl`을 **학습 전용**으로 축소하고,
벤치마크의 유일한 진입점을 `run_neural_benchmark.jl`로 고정했다.

**V1 결과에 대한 영향: 없음.** V1 보고서가 인용하는 `neural_benchmark.csv`는
`run_neural_benchmark.jl`(고정스텝 RK4)이 생성한 것이며, 중복 코드는 실행되어
결과를 남긴 적이 없다 (1차 실행은 파일을 쓰기 전에 중단됨,
`docs/EXPERIMENT_PROTOCOL.md` §2.1).

## B. **시간 정규화 불일치 — 학습되지 않은 영역에서 외삽하고 있었다**

**문제.** V1의 벡터장은 `f_θ(h, t)`이고 신경망 입력은 `[h, t/T_nvf]`이며
`T_nvf = TR["T"] = 10.0`(학습 지평)로 고정된다. 그러나

* 학습: `t ∈ [0, 10]` → 시간 입력 ∈ `[0, 1]`
* 평가: `t ∈ [0, 20]` → 시간 입력 ∈ **`[0, 2]`**

즉 **모든 평가 궤적의 후반 절반에서 신경망이 시간 입력을 2배 외삽한다.**

게다가 교사(reference)는

    dh/dt = −κ(h − ½) − γ(h − ½)³

로 **자율계(autonomous)**이며 `t`에 전혀 의존하지 않는다. 따라서 시간 입력은
과제 해결에 불필요하고, 순수하게 외삽 오차만 유입시킨다.

**V1 결과에 대한 영향: 잠재적으로 있음, 방향은 불명.** V1 §14의 결론
("게이트는 진폭 외삽에서만 효과, Cantor 특이성 없음")은 모든 변형이 **동일한**
불일치를 겪으므로 변형 간 비교로서는 여전히 공정하다. 그러나 절대 수준의
추적 오차는 과대평가되었을 수 있고, 후반 시간대의 거동에는 이 인공물이 섞여
있다. V1 보고서에서 이 점을 언급하지 않은 것은 누락이다.

**조치.** `src/NeuralODEModel.jl`에 `use_time` 옵션을 추가했다.
**기본값 `true`로 V1 거동을 정확히 보존**하며, `use_time = false`이면
자율 벡터장 `f_θ(h)`가 된다 (입력 1개, 파라미터 수 감소).
자율 대조 실험은 `scripts/v2/run_v1_autonomous_check.jl`이 수행하고 결과를
`results/v2/raw/`에 쓴다. **V1 원자료는 덮어쓰지 않는다.**

## C. `endpoint_instability`의 설명 문구 (경미)

`src/CantorCore.jl`의 `endpoint_instability` docstring은 오차 증폭계수 `3ⁿ·eps`를
먼저 제시하여 그것이 원인인 듯 읽힐 수 있다. 실제 원인은 V1 보고서 §9와
`docs/RESULTS.md` R8이 정확히 서술한 대로 **끝점이 스위칭면 위에 있어 Float64
반올림 방향이 판정을 결정하는 것**이며(그래서 비율이 1/2로 수렴한다), 증폭은
부차적이다. 코드 주석과 보고서 본문은 일치하며, docstring의 서술 순서만
오해를 부를 수 있다. **결과에 영향 없음.**

## D. V2에서 물려받되 바꾼 것

`src/v2/CantorBarrier.jl`의 `cantor_gap_list`는 구간 끝점을
`Rational{BigInt}`로 계산한 뒤 **한 번만** 반올림하고, 오른쪽 끝점을
`a + 3.0^{-k}`로 설정한다. V1이 발견한 재귀 부동소수점 조건수 문제
(`docs/BASELINE_AUDIT.md`)를 애초에 피하기 위한 것이며, V1 코드는 재현성을
위해 그대로 둔다. 이 차이가 없으면 `n ≥ 10`에서 gap 폭이 `3^{-k}`와
상대오차 `10^{-9}` 이상 어긋난다 (V2 테스트 §2가 정확 유리수 기준으로 검증).
