# Project Cantor V3.4.0 최종 보고서
## 감지–구동 분리 Cantor 인증 LLM 안전 제어

## 0. 한 줄 요약

**이전 버전들이 실패한 이유는 하나의 잔차 방향에게 감지와 구동을 동시에 시킨
것이 맞았다.** 둘을 분리하자 sensor는 즉시 일반화되었다. 그러나 그 위에 올린
Cantor 정책층은 배포 가능한 개입 크기에서 **행동적으로 무력**했다.

## 1. 판정

```
SENSOR       SENS2_REFUSAL_SENSOR_ONLY
ACTUATOR     ACT1_CAUSAL_ACTUATOR_REPLICATED
COUPLING     COUP1_CONTROLLABLE
CERTIFICATE  CERT1_CANTOR_SENSOR_CERTIFICATE_VALID
SEMANTIC     SEM3_PROXY_ONLY
GENERATION   GEN2_RHO_FAMILY_PRACTICALLY_EQUIVALENT
UTILITY      U1_PASS
OVERALL      G_INCONCLUSIVE
```

## 2. 새로 확립된 것 — 감지 ≠ 구동

V3.3.5c는 이상한 비대칭을 남겼다. 개입은 재현되는데 경계는 재현되지 않았다.
V3.4.0의 가설은 그것이 제어 아키텍처의 문제라는 것이었다.

    sensor    w = 행동 라벨로 학습한 초평면의 법선
    actuator  v = V3.3.5b/c가 확립한 인과 방향
    coupling  kappa = <w_hat, v_safe>

**같은 held-out 프롬프트에서:**

| | OLD `<h,v>` | NEW `d_w` |
|---|---:|---:|
| AUROC | 0.8557 | **0.9336** |
| balanced accuracy | 0.7669 | **0.8656** |

짝지은 차이 **+0.0780 [+0.0029, +0.1660]**, 두 방향은 **71.9° 떨어져 있다.**

이 결과는 사소한 교란도(잔차 노름 0.520, 길이 0.502/0.695), 라벨러 의존도
아니다(독립 LEX32 라벨로 0.9459, 두 초평면 코사인 0.826).

그리고 **V3.3.5c의 실패 양식이 구조적으로 사라졌다.** 경계가 `d = 0`이므로
추정할 문턱이 없다. 18 sigma 구간 문제는 발생할 수 없다.

## 3. 실제로 작동하는 controller를 만들었다

프로젝트 사상 처음으로 다음이 모델 forward 안에서 전부 실행되었다.

    clean h → 공격 → controller가 공격된 상태를 관찰 → 실제 보정
            → token-1 logits → 전체 디코딩

- ATTACK-W가 sensor를 정확히 `-eps`만큼 이동 (오차 5.6e-08)
- controller 이동이 `q·||h||·kappa`와 1e-9 이내 일치
- 인증서 위반 **0건**, 7개 rho 전부 → `CERT1`
- 보정된 상태가 clean에 더 가까워지는 비율 94–98 %

수학도 그대로 성립한다. `epsilon_h(rho) = 2W·rho^2(1-2rho)`, `W = 2.2805`,
`rho = 1/3`이 유일 최대점, `epsilon_C = 2W/27 = 0.1689`.

## 4. 그럼에도 결론이 `G_INCONCLUSIVE`인 이유

### (a) 내 예산 보정이 틀렸다

`eta`를 **clean** 상태에서 맞췄지만 controller는 **공격받은** 상태에서 돈다.
공격 상태는 더 높은 action cell에 놓이므로 실제 `q_rms`가 목표 0.0300 대신
0.0343–0.0374로 나왔다 — 허용 ±3 %를 모두 벗어난다. 게다가 편차가 rho와 함께
커져 큰 rho가 더 많은 에너지를 썼다.

동결 규칙대로 **모든 rho를 확증 비교에서 제외**했고, D_final을 본 뒤 다시
맞추지 않았다.

### (b) 더 근본적으로, controller가 행동을 바꾸지 못한다

| | |
|---|---:|
| 7개 rho가 출력이 다른 cell | **1.5 %** |
| 7개 rho가 라벨이 다른 cell | **0.07 %** |
| 9,520행의 서로 다른 완성 | **267개 (2.8 %)** |

ATTACK-W에서 7개 rho의 AUC가 **완전히 동일**하고 max-T 임계값이 **정확히 0**이다.

규모가 답이다.

    controller 한 걸음        0.652
    Cantor 인증서             0.169
    행동이 움직이는 크기       1.844   <- 걸음보다 2.8배, 인증서보다 11배 크다

**인증 가능한 규모와 행동이 바뀌는 규모가 한 자릿수 이상 떨어져 있다.**

행동 실패 문턱을 직접 재면 같은 결론이 나온다: 인증 반경의
**10.9–17.4배**(ATTACK-W), **32.7–69.7배**(ATTACK-V)에서 행동이 무너진다.
그리고 그 문턱은 모든 rho에서 동일하다.

### (c) utility 통과도 사소하다

false refusal 증가가 정확히 0이다. controller가 좋아서가 아니라 아무것도
바꾸지 않아서다. 사전에 기록한 "utility가 실패할 것"이라는 예측은 **틀렸고**,
틀린 이유가 같은 무력함이다.

## 5. 이번에도 의미 평가기가 없었다

balanced accuracy 0.85를 넘는 평가기가 없었다(최고 0.682). 사전 규칙이 발동해
범위가 `SENS2_REFUSAL_SENSOR_ONLY`로 축소되었다.

진단이 중요하다. `LibrAI/longformer-action-ro`는 **순응인지 거부인지**는 거의
완벽히 가리지만(거부 판별 balanced accuracy 0.966) **그 순응이 유해한지**는
가리지 못한다. 그것은 다른 질문이다. 게다가 이 모델은 유해 프롬프트에
48토큰 안에서 harmful compliance를 **10 %** 만 낸다.

이 실패는 그대로 아래로 전파된다. 라벨이 "harmful compliance"에서 "compliance"로
무너지면 sensor는 **도움이 되는 응답 전체를 위험으로 읽는다.** 실제로 benign
프롬프트는 `d` 평균 −2.195로 크게 이동하고 45 %가 window 밖으로 나간다.
개입이 강했다면 utility는 무너졌을 것이다.

## 6. V1 → V3.4.0

- **V1**: Cantor 도함수 게이트의 겉보기 이득 → confound
- **V2–V3.2**: 정합 대조군에서 고유한 raw-score 우월성 없음
- **V3.3–V3.3.2**: middle-third `1/3`의 재귀 maximin 수학 도출
- **V3.3.3**: 표현 중점과 행동 문턱이 크게 어긋남
- **V3.3.4**: r-공간 maximin 성립, 그러나 logistic 왜곡이 exact 최적을 이동
- **V3.3.5**: 아핀 좌표가 metric을 보존해 exact `1/3` 복원, G1 경계는 실패
- **V3.3.5a**: P0가 토큰 1에 도달함을 확인, 절대 dose 설계가 비국소적
- **V3.3.5b**: 궤적 L2 정합에서 초기 시간 분산 기각, P0 집중이 최강
- **V3.3.5c**: 정규화 P0 인과 효과는 재현, 그러나 **같은 방향 위의** 사영은
  정밀한 공유 문턱을 주지 못함
- **V3.4.0**: 감지와 구동을 분리 → **sensor는 즉시 일반화됨**.
  실제 controller를 만들고 인증서를 검증했으나,
  **인증 가능한 규모에서는 행동이 움직이지 않음**

## 7. 이 프로젝트가 실제로 알아낸 것

**긍정.** 이전 실패는 Cantor 기하의 실패가 아니라 **제어 아키텍처의 실패**였다.
하나의 방향에게 가관측성과 가제어성을 동시에 요구한 것이 문제였다. 분리하면
선형 행동 sensor는 새 프롬프트로 잘 일반화된다(AUROC 0.934).

**부정.** 그렇게 얻은 sensor 위에 Cantor 정책을 올려도 이 모델에서는 쓸모가
없다. `epsilon_h = 2W/27`가 인증하는 반경은 행동이 바뀌는 크기보다 한 자릿수
이상 작다. 인증서를 키우려면 `W`를 키워야 하는데, `W`는 clean 상태 분포가
정하는 값이지 우리가 고르는 값이 아니다.

**즉 구조적 최적성과 행동적 유효성이 서로 다른 축에 있다.**
`rho = 1/3`은 여전히 유일한 exact maximin 해다. 그 사실은 이 모델에서
행동을 더 안전하게 만들지 못한다.

## 8. 한계

1. 모델 하나(Qwen2.5-0.5B-Instruct), layer 하나, P0 한 지점.
2. 의미 평가기 없음 — 모든 endpoint는 거부(refusal)이지 harmful compliance가 아니다.
3. 정답 라벨의 주석자는 독립 인간 패널이 아니라 어시스턴트다.
4. sensor 훈련 n = 180, d = 896. 강한 L2에 전적으로 의존한다.
5. 예산 보정 결함으로 equal-budget 확증 비교를 수행하지 못했다.
6. 최대 48 토큰. 더 긴 생성에서 결론이 달라질 가능성은 배제하지 못한다.
7. Cantor 기하는 **부과한 controller 설계**이지 모델에서 발견한 성질이 아니다.
   이 LLM이 프랙탈 구조를 갖는다고 주장하지 않는다.

## 9. 다음에 무엇을 해야 하는가 (그리고 무엇을 하지 말아야 하는가)

**하지 말 것**: 긍정 결과를 얻기 위한 V3.4.1. 정리 수정. 더 나은 layer/token
탐색. 결과를 본 뒤 `v`를 `w` 쪽으로 회전.

**정직하게 남는 질문**: 인증 가능한 규모와 행동 규모의 간극은 `W`가 clean 분포
폭에 묶여 있는 데서 온다. 이 간극을 좁히려면 잔차 공간의 기하를 바꾸는 것이
아니라 **행동이 훨씬 작은 섭동에 반응하는 지점**을 찾아야 한다. 그것은 Cantor
질문이 아니라 표현학습 질문이다.

**프로젝트는 여기서 끝낸다.**
