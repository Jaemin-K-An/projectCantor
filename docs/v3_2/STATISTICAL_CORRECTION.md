# V3.2 통계 보정 — 왜 goal이 표집 단위인가

## 1. 문제

V3.1은 `(goal × attack × Δ × ε)` 셀을 독립 관측으로 보고 부트스트랩했다.
그러나 같은 goal의 20개 조건은 **독립 표본이 아니다.** "폭탄 제조법"이
모든 조건에서 어렵다면 그것은 컨트롤러 품질에 대한 20개의 증거가 아니라
**1개**다.

일반화하려는 모집단은 **조건이 아니라 유해 목표**다. 따라서 추론 단위도
goal이어야 한다.

## 2. 절차 (`llm/src/cantor_guard_v32/cluster_stats.py`)

```
cluster_bootstrap_by_goal:
  goal ID를 복원추출 → 뽑힌 goal의 (attack, Δ, ε) 관측 전체를 함께 가져옴
  → goal 내 평균차 → goal 간 평균
```

goal마다 **동일 가중**이므로 조건 수가 많은 goal이 결과를 지배하지 않는다.
`hierarchical_bootstrap`은 goal을 뽑은 뒤 그 안에서 attack까지 재표집해
attack 템플릿 자체가 소표본이라는 사실도 반영한다(민감도 분석).

`naive_cell_bootstrap`은 V3.1 절차를 **나란히 보여주기 위해서만** 유지하며
어떤 주장에도 쓰지 않는다.

## 3. 검증

상관 구조가 알려진 합성 데이터(goal 10개 × 조건 40개, goal간 SD 0.10,
goal내 SD 0.01)에서:

| 절차 | 95 % CI 반폭 |
|---|---|
| naive (400 셀) | 0.0083 |
| **군집 (10 goal)** | **0.0526** |
| 계층 | 0.0509 |

군집 CI가 **6.4배** 넓다 — 의사반복이 정확히 검출된다. naive 절차는
goal이 10개뿐인데 400개의 증거가 있는 것처럼 행동한다.

## 4. 동등성

SESOI **δ = 0.03**를 유지한다(V3.1에서 데이터를 보기 전에 정한 값,
변경하지 않는다). 판정: **군집 95 % CI가 [−0.03, +0.03]에 완전히 포함**될 때만
동등. 통상 TOST는 90 % CI를 쓰므로 95 % CI 사용은 **보수적**이다.

## 5. 보고 규칙

* 모든 CI는 군집 기준. naive는 감사 표에만 병기한다.
* 검정력이 부족한 비교(사전 계산)의 null은 **INCONCLUSIVE**로 표기하며
  결코 동등성의 증거로 쓰지 않는다.
* 군집화가 결론을 **바꾼** 비교는 전부 명시한다(위 2건).
