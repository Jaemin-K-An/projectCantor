## 1. 무효 사유 — 실현 예산 정합 실패

사전등록(`PREREGISTRATION.md` §2)은 실현 비용
`C_rms = sqrt(E[q²])`, `q = ‖Δh‖/‖h‖`를 목표 **0.02**에 맞추는 것을
**primary fairness constraint**로 규정했다. 허용 오차 ±3 %.

실측 결과:

| controller | 달성 `C_rms` | 목표 대비 | 판정 |
|---|---|---|---|
| `T1_true_constant` | 0.01998 | **−0.1 %** | OK |
| `T4_periodic` | 0.01735 | −13.3 % | **FAIL** |
| `T6_center_anchored` | 0.01672 | −16.4 % | **FAIL** |

**9개 중 8개가 정합에 실패했다.** 특히 비교의 핵심인
`T7_cantor`(−17.7 %)와 `T2_global_smooth`(−53.3 %)의 실현 개입량이
**2배 가까이 다르다.** 이 상태의 비교는 "같은 예산에서 어느 기하가 나은가"를
묻는 것이 아니다.

harness §49 STOP D: *"actual budgets ±3 % 이내 match 실패 → 해당 comparison
무효."* 따라서 **v1 시험을 무효로 선언한다.**

## 2. 근본 원인 — probe와 test의 생성 길이 불일치

`run_llm_direct.py`의 η 교정은

```python
_, st = generate31(..., max_new_tokens=8, ...)   # probe
eta = target / st["C_rms"]
```

로 **8 토큰** probe에서 `C_rms(η=1)`을 재고, 본 시험은 **48 토큰**으로
돌렸다.

`q = c(m̂)/‖h‖`이고 `c`는 margin `m̂`의 함수이므로, `q`가 `η`에 선형인 것은
**margin 분포가 고정된 경우에 한한다.** 생성이 진행되면 margin 분포가
이동하므로(V3 PHASE 3이 측정한 바로 그 현상 — 첫 생성 토큰과 이후가
1.65 σ 다르다) 8 토큰 probe의 분포는 48 토큰 실행의 분포와 다르다.

**상태 무관 컨트롤러만 이 오류에서 자유롭다** — `T1_true_constant`가
정확히 −0.1 %로 맞은 이유이며, 이것 자체가 원인의 확증이다.

부차 원인: `q_cap = 0.05`가 다척도 계열에서 거의 구속적이다
(`C_max` 0.0449–0.0455). 상한이 걸리면 `q`가 `η`에 선형이 아니게 된다.

---

## 3. 수정 (protocol v2)

1. η 교정을 **본 시험과 동일한 `max_new_tokens = 48`**로 수행한다.
2. probe를 대표적인 `(Δ, ε)` 혼합에서 수행한다
   (`Δ ∈ {0, ±q95}`, `ε ∈ {0, 10}`) — margin 분포를 실제 시험과 일치시킨다.
3. 상한 비선형성을 흡수하기 위해 **η 추정을 1회 반복**한다
   (`η₂ = η₁ · target / C_rms(η₁)`).
4. 최종 실행의 달성 `C_rms`를 다시 측정하고, ±3 % 밖이면 해당 family를
   matched 비교에서 **제외**하고 그 사실을 보고한다.

## 4. v1에서 유지되는 것

* **지표 도달가능성 게이트 통과** (0.251 → 0.033, 분산 > 0, gibberish/빈 응답
  불인정). 이는 예산 정합과 무관하며 v2에서도 동일하게 재검증한다.
* **유틸리티 측정**: benign false refusal 0.458–0.500, coherence 0.9985–0.9987.
  개입이 작아 출력이 전혀 손상되지 않았다 — V2의 붕괴 문제가 재현되지 않음을
  확인한 것은 유효하다.
* v1의 판정(`D_CANTOR_INFERIOR`)은 **무효 예산 위에서 나온 것이므로 최종
  결론으로 사용하지 않는다.** 참고로만 기록한다.
